# Brimacombe crawler

Brimacombe crawler location:

```text
crawler/mountains/brimacombe/
```

The crawler is split into two phases:

1. `json_generators/` fetches Brimacombe pages and writes normalized JSON files.
2. `snapshot_generator.py` rebuilds the combined snapshot and missing-column report, then `main.py` optionally sends the snapshot to Convex.

Individual JSON generators do not push data to Convex.

`static_infos.json` contains manually maintained resort identity/contact data. It is not fetched from the Brimacombe pages.

## JSON generator phase

Run generators directly from the Brimacombe directory:

```powershell
cd crawler/mountains/brimacombe
python json_generators/hours-of-operation.py
python json_generators/lift-rates.py
python json_generators/rentals.py
python json_generators/weather-and-status.py
```

Each generator writes its JSON beside its Python file in `json_generators/`.

`dtos.py` is a shared conversion module. It is also discovered by `snapshot_generator.py` because that script runs every `json_generators/*.py` file. Running `dtos.py` directly has no data-fetching side effect.

### Hours of operation

Source:

```text
https://brimacombe.ca/contact-us/
```

`hours-of-operation.py`:

- Finds an `h2`, `h3`, or `h4` containing `HOURS OF OPERATION`.
- Reads paragraph lines below the heading.
- Detects section headings from `<strong>` elements.
- Associates day labels with their time text.
- Normalizes the result through `to_hours()`.
- Writes:

```json
{
  "hours": [
    {
      "name": "Guest & Member Services",
      "hours": [
        { "day": "Monday", "time": "9:00 a.m. to 4:00 p.m." }
      ]
    }
  ],
  "resortId": "brimacombe",
  "sourceUrl": "https://brimacombe.ca/contact-us/",
  "updatedAt": 0
}
```

`updatedAt` is generated with the current Unix timestamp in milliseconds. The example uses `0` only to show shape.

### Lift rates

Source:

```text
https://brimacombe.ca/plan-your-visit/lift-tickets/
```

`lift-rates.py`:

- Reads the first HTML table.
- Uses table header cells as source column names.
- Converts rows to `rates.items` through `to_rates_dto()`.
- Maps `Age Categories` to `items[].name`.
- Maps every other source column to `items[].prices[]` with `label` and `value`.
- Writes `rates`, `resortId`, `sourceUrl`, and `updatedAt`.

Example normalized item:

```json
{
  "name": "Adult (18+)",
  "prices": [
    {
      "label": "Friday to Sunday & Holidays Valid up to 4 Hours",
      "value": "$70"
    }
  ]
}
```

### Rentals

Source:

```text
https://brimacombe.ca/plan-your-visit/rentals/
```

`rentals.py` reads the first three HTML tables:

| Table index | Output section |
| ---: | --- |
| `0` | `Individual Rental Packages` |
| `1` | `Individual Rental Items` |
| `2` | `7-Week Program Lesson Rentals` |

`to_rentals_dto()` converts each section to:

```json
{
  "name": "Section name",
  "items": [
    {
      "name": "Rental item or package",
      "prices": [
        { "label": "Cost", "value": "$54.00" }
      ]
    }
  ]
}
```

The converter identifies item names using keys containing `package`, `rental item`, `name`, or `item`. Remaining row columns become price labels.

### Weather and status

Source:

```text
https://brimacombe.ca/at-the-brim/snow-conditions-and-trails/
```

`weather-and-status.py` reads up to three HTML tables:

| Table index | Source | Normalized output |
| ---: | --- | --- |
| `0` | Trails | `trails` |
| `1` | Terrain parks | `terrainParks` |
| `2` | Lifts | `lifts` |

Trail rows contain number, name, difficulty, day status, and night status. Lift rows contain identifier, name, day status, and night status. `to_weather_dto()` produces:

- `lifts[]`: `name`, `status`, `dayStatus`, `nightStatus`, `identifier`
- `trails[]`: `name`, `status`, `difficulty`, `dayStatus`, `nightStatus`, `number`
- `terrainParks[]`: same normalized trail shape, with the park code stored as `number`
- `rawData`: original crawler data
- `resortId`, `sourceUrl`, `updatedAt`

`liftsSummary` and `trailsSummary` are not generated by the current Brimacombe crawler.

## Snapshot generation

From the Brimacombe directory:

```powershell
cd crawler/mountains/brimacombe
python snapshot_generator.py
```

`snapshot_generator.py` performs these steps:

1. Finds every `json_generators/*.py` file in sorted filename order.
2. Runs each script with the current Python interpreter.
3. Loads the four generated JSON files.
4. Loads `static_infos.json`.
5. Builds the five-table document:
   - `resorts`
   - `resortHours`
   - `resortRates`
   - `resortRentals`
   - `weatherAndStatus`
6. Writes `snapshot_generator.json`.
7. Checks every configured schema column for missing values.
8. Writes `snapshot_generator_report.json`.

The generator runs external page requests through the four crawler scripts. It does not call Convex.

### Snapshot output

`snapshot_generator.json` contains:

```json
{
  "resortId": "brimacombe",
  "tables": [
    {
      "table": "resorts",
      "content": {}
    }
  ]
}
```

The actual file contains all five table contents. Columns are represented by each table's content object; no separate `columns` array is emitted.

### Missing-column report

`snapshot_generator_report.json` lists missing values by table:

```json
{
  "resortId": "brimacombe",
  "tables": [
    {
      "table": "resorts",
      "missingColumns": ["rating", "ticketUrl", "tubbingPrice"]
    }
  ],
  "missingColumnCount": 5
}
```

The report is informational. It does not stop snapshot generation or Convex writes.

## Convex population

Prerequisites:

- Python environment configured for the crawler.
- Node dependencies installed, including the Convex CLI.
- Convex configuration in `.env`, `.env.local`, or the crawler environment:
  - `CONVEX_DEPLOYMENT`, or
  - `CONVEX_DEPLOY_KEY` / `CONVEX_ADMIN_KEY`.

`crawler/convex_client.py` invokes the Convex CLI with `node` and runs internal mutations. It does not expose keys in logs.

Run the complete Brimacombe flow:

```powershell
cd crawler/mountains/brimacombe
python main.py
```

`main.py`:

1. Runs `snapshot_generator.py`.
2. Loads `snapshot_generator.json`.
3. Rejects duplicate table names.
4. Rejects missing or unexpected table names.
5. Requires metadata on `resortHours`, `resortRates`, `resortRentals`, and `weatherAndStatus`.
6. Verifies every table uses `resortId = brimacombe`.
7. Sends the `resorts` document through `resorts:saveMany`.
8. Sends hours through `resortHours:save`.
9. Sends rates through `resortRates:save`.
10. Sends rentals through `resortRentals:save`.
11. Sends weather/status through `weatherAndStatus:save`.

### Duplicate behavior

Repeated runs are upserts keyed by `resortId`:

- `resorts:saveMany` queries `resorts.by_resort_id`; patches the existing document or inserts one.
- `resortHours:save` queries `resortHours.by_resort`; replaces the existing document or inserts one.
- `resortRates:save` queries `resortRates.by_resort`; replaces the existing document or inserts one.
- `resortRentals:save` queries `resortRentals.by_resort`; replaces the existing document or inserts one.
- `weatherAndStatus:save` queries `weatherAndStatus.by_resort`; replaces the existing document or inserts one.

The main script sends one document per table and rejects duplicate table entries before any push call.

## Validation

Validate generated JSON without fetching pages:

```powershell
python -m json.tool json_generators/hours-of-operation.json > $null
python -m json.tool json_generators/lift-rates.json > $null
python -m json.tool json_generators/rentals.json > $null
python -m json.tool json_generators/weather-and-status.json > $null
python -m json.tool snapshot_generator.json > $null
python -m json.tool snapshot_generator_report.json > $null
```

Validate Python syntax:

```powershell
python -c "import ast; from pathlib import Path; paths=[Path('snapshot_generator.py'), Path('main.py'), *Path('json_generators').glob('*.py')]; [ast.parse(path.read_text(encoding='utf-8'), filename=str(path)) for path in paths]"
```

Do not run `main.py` unless Convex credentials and the target deployment are intentional. It performs external page fetches and Convex mutations.
