# Fall Line mobile development

The Expo app uses the existing Convex backend and the website's public resort
image assets. It does not include admin screens or require public users to sign in.

## Configuration

1. Install workspace dependencies from the repository root with `pnpm install`.
2. Copy `.env.example` to `.env.local` in this directory and configure:
   - `EXPO_PUBLIC_CONVEX_URL`: the same Convex deployment used by the website.
   - `EXPO_PUBLIC_SITE_URL`: the public HTTPS website origin serving
     `/assets/resorts/...`.
   - `EXPO_PUBLIC_SUPPORT_EMAIL`: optional; leave blank when no support address is configured.
   - `GOOGLE_MAPS_IOS_API_KEY` and `GOOGLE_MAPS_ANDROID_API_KEY`: separately restricted
     Maps SDK keys.
   - `IOS_BUNDLE_IDENTIFIER` and `ANDROID_PACKAGE`: app identifiers matching the
     corresponding key restrictions. Defaults are development placeholders;
     configure real identifiers before creating a signed build.
3. Enable Google Maps SDK for iOS and Android in the Google project, and restrict
   iOS keys by bundle identifier and Android keys by package and signing
   certificate fingerprint. Client Maps keys are embedded in app binaries and
   are not secrets; do not include Clerk secrets or Convex deploy keys.

The repository `.easignore` excludes local environment files and credentials.
For EAS, configure these values through the appropriate EAS environment rather
than uploading local `.env` files. Review the archive and target before uploading.
The existing Convex function changes must be deployed to the intended Convex
environment before the publication guards protect that environment.

## Development builds

Google Maps on iOS requires a custom development build; Expo Go on iOS cannot
verify that provider. On Windows, an iPhone development build requires an EAS
account, Apple Developer membership, signing credentials, and a registered
iPhone. Alternatively use a Mac with Xcode. Android builds can use Android
Studio locally or EAS. Creating cloud builds uploads the project to Expo.

From this directory, after configuring Expo/EAS and device prerequisites:

```sh
pnpm start
pnpm android
# On macOS with Xcode:
pnpm ios
```

For an EAS build, use `eas build --platform ios --profile development` or
`eas build --platform android --profile development` from this directory.
Installing a custom development build is separate from starting Metro.

Useful checks from the repository root:

```sh
pnpm test
pnpm --filter @fall-line/shared typecheck
pnpm --filter @fall-line/mobile typecheck
pnpm --filter @fall-line/mobile lint
pnpm --filter @fall-line/mobile exec expo install --check
```

## Data and images

The app subscribes directly to public Convex queries. Its bundled image
manifest is `src/data/resortAssets.json`, generated by
`scripts/generateResortAssets.mjs`. New image manifest entries require an
updated mobile JavaScript bundle. The website must host the matching image
files. Missing or failed hero images use the bundled brand icon.

The app supports foreground location with permission, manual region selection,
and saved language/region/map split. It displays an offline notice and retries
Convex connections, but does not offer offline maps or persistent resort data.
